Absolutely. Let’s do **FUNCTION 2 — Strings + Streams**. This is where Stream interviews become much more interesting because you have to combine `chars()`, `mapToObj()`, `groupingBy()`, `counting()`, ordering, and sometimes `LinkedHashMap`.

# FUNCTION 2 — String & Character Stream Problems

We'll focus on the **patterns**, not memorizing 20 isolated solutions.

## 1. Convert a String into a Stream of characters

Suppose:

```java
String str = "hello";
```

The first thing to understand is:

```java
str.chars()
```

This gives an `IntStream`, not `Stream<Character>`.

```java
str.chars()
```

Conceptually:

```text
h → 104
e → 101
l → 108
l → 108
o → 111
```

Because `char` is represented using an integer code internally.

To get actual `Character` objects:

```java
str.chars()
   .mapToObj(c -> (char) c)
```

Now you have:

```text
h
e
l
l
o
```

### Important interview pattern

```java
string.chars()
      .mapToObj(c -> (char) c)
```

Memorize this.

# 5. Character frequency ⭐⭐⭐

Input:

```java
String str = "banana";
```

Expected:

```text
b = 1
a = 3
n = 2
```

The most important solution:

```java
Map<Character, Long> frequency =
        str.chars()
           .mapToObj(c -> (char) c)
           .collect(Collectors.groupingBy(
                   Function.identity(),
                   Collectors.counting()
           ));
```

Result:

```text
{a=3, b=1, n=2}
```

### Understand every piece

```java
str.chars()
```

↓

```java
.mapToObj(c -> (char) c)
```

↓

```java
.groupingBy(...)
```

↓

```java
Function.identity()
```

means:

> Group by the character itself.

Then:

```java
Collectors.counting()
```

means:

> Count how many occurrences are in each group.

So:

```text
banana

b → [b]       → 1
a → [a,a,a]   → 3
n → [n,n]     → 2
```

---

# 6. Preserve character insertion order ⭐⭐⭐

This is a common follow-up.

The default `groupingBy()` uses `HashMap`.

If you want insertion order:

```java
Map<Character, Long> frequency =
        str.chars()
           .mapToObj(c -> (char) c)
           .collect(Collectors.groupingBy(
                   Function.identity(),
                   LinkedHashMap::new,
                   Collectors.counting()
           ));
```

Now:

```text
banana

b → 1
a → 3
n → 2
```

The order is preserved based on first appearance.

### Interview question

> Why `LinkedHashMap`?

Answer:

> `HashMap` does not guarantee encounter/insertion order, while `LinkedHashMap` maintains insertion order.

# 7. Find duplicate characters ⭐⭐⭐

Input:

```java
String str = "programming";
```

We want:

```text
r
g
m
```

Solution:

```java
List<Character> duplicates =
        str.chars()
           .mapToObj(c -> (char) c)
           .collect(Collectors.groupingBy(
                   Function.identity(),
                   Collectors.counting()
           ))
           .entrySet()
           .stream()
           .filter(e -> e.getValue() > 1)
           .map(Map.Entry::getKey)
           .toList();
```

The important pattern is:

```text
String
 ↓
frequency Map
 ↓
entrySet()
 ↓
filter(count > 1)
 ↓
map(key)
```

This pattern will appear repeatedly.

# 9. First non-repeated character ⭐⭐⭐

This is **very important for interviews**.

Input:

```java
String str = "swiss";
```

Expected:

```text
w
```

We need two things:

1. Frequency
2. Original order

Therefore use `LinkedHashMap`.

```java
Character result =
        str.chars()
           .mapToObj(c -> (char) c)
           .collect(Collectors.groupingBy(
                   Function.identity(),
                   LinkedHashMap::new,
                   Collectors.counting()
           ))
           .entrySet()
           .stream()
           .filter(e -> e.getValue() == 1)
           .map(Map.Entry::getKey)
           .findFirst()
           .orElse(null);
```

### Why `LinkedHashMap`?

Imagine:

```text
swiss

s → 3
w → 1
i → 1
```

We need the **first** character whose count is 1.

That means order matters.

```text
HashMap       → order not guaranteed ❌
LinkedHashMap → insertion order ✅
```

# 10. First repeated character

Input:

```java
String str = "swiss";
```

Answer:

```text
s
```

Be careful here.

The question says **first character that repeats**, not simply a character whose frequency > 1.

We need to preserve encounter order.

One Stream solution:

```java
Character result =
        str.chars()
           .mapToObj(c -> (char) c)
           .collect(Collectors.groupingBy(
                   Function.identity(),
                   LinkedHashMap::new,
                   Collectors.counting()
           ))
           .entrySet()
           .stream()
           .filter(e -> e.getValue() > 1)
           .map(Map.Entry::getKey)
           .findFirst()
           .orElse(null);
```

For `swiss`, this gives:

```text
s
```

### BUT!

There is a subtle difference between:

> first repeated character

and

> first character whose total frequency is greater than 1.

For many interview inputs they produce the same answer, but conceptually they are different.

A true "first repetition encountered while scanning left-to-right" is better represented by stateful logic or a frequency lookup.

# 11. Character with maximum frequency ⭐⭐⭐

Input:

```java
String str = "banana";
```

Answer:

```text
a
```

First create frequency:

```java
Map<Character, Long> frequency =
        str.chars()
           .mapToObj(c -> (char) c)
           .collect(Collectors.groupingBy(
                   Function.identity(),
                   Collectors.counting()
           ));
```

Then:

```java
Character max =
        frequency.entrySet()
                 .stream()
                 .max(Map.Entry.comparingByValue())
                 .map(Map.Entry::getKey)
                 .orElse(null);
```

This introduces an important pattern:

```java
map.entrySet()
   .stream()
   .max(Map.Entry.comparingByValue())
```

You'll see this everywhere in Java interviews.

# 12. Character with minimum frequency

Same thing:

```java
Character min =
        frequency.entrySet()
                 .stream()
                 .min(Map.Entry.comparingByValue())
                 .map(Map.Entry::getKey)
                 .orElse(null);
```

# 13. Sort characters by frequency ⭐⭐

Input:

```text
banana
```

Frequency:

```text
a → 3
n → 2
b → 1
```

Solution:

```java
List<Map.Entry<Character, Long>> result =
        frequency.entrySet()
                 .stream()
                 .sorted(Map.Entry.<Character, Long>
                         comparingByValue()
                         .reversed())
                 .toList();
```

The pattern:

```text
Map
 ↓
entrySet()
 ↓
stream()
 ↓
sorted(comparingByValue())
```

is extremely useful.

# 14. Check whether two strings are anagrams ⭐⭐⭐

Input:

```text
listen
silent
```

They are anagrams.

### Stream solution

One simple approach is sorting:

```java
boolean isAnagram =
        s1.chars()
          .sorted()
          .boxed()
          .toList()
          .equals(
              s2.chars()
                .sorted()
                .boxed()
                .toList()
          );
```

For example:

```text
listen → eilnst
silent → eilnst
```

Therefore:

```text
true
```

### But interview follow-up:

> Can you do it without sorting?

Yes.

Use character frequencies:

```java
Map<Integer, Long> freq1 =
        s1.chars()
          .boxed()
          .collect(Collectors.groupingBy(
                  Function.identity(),
                  Collectors.counting()
          ));

Map<Integer, Long> freq2 =
        s2.chars()
          .boxed()
          .collect(Collectors.groupingBy(
                  Function.identity(),
                  Collectors.counting()
          ));

boolean result = freq1.equals(freq2);
```

This gives you:

```text
Sorting approach:
O(n log n)

Frequency approach:
O(n) average
```

That's exactly the kind of follow-up an interviewer may ask.

# 15. Remove duplicate characters

Input:

```text
programming
```

We want:

```text
progamin
```

Using:

```java
String result =
        str.chars()
           .distinct()
           .mapToObj(c -> String.valueOf((char) c))
           .collect(Collectors.joining());
```

Output:

```text
progamin
```

### Why does this preserve order?

Streams over an ordered source such as `String.chars()` have an encounter order, and `distinct()` maintains it for sequential ordered streams.

# 19. Sum digits in a String

Input:

```text
"a1b2c3"
```

Answer:

```text
6
```

```java
int sum =
        str.chars()
           .filter(Character::isDigit)
           .map(c -> c - '0')
           .sum();
```

Important:

```java
'5' - '0' = 5
```

because characters have numeric codes.

# 20. Reverse a String

Streams aren't naturally designed for reversing strings, but you can do it.

```java
String reversed =
        IntStream.range(0, str.length())
                 .mapToObj(i -> str.charAt(str.length() - 1 - i))
                 .map(String::valueOf)
                 .collect(Collectors.joining());
```

For:

```text
hello
```

we get:

```text
olleh
```

### But interview wisdom:

If asked:

> "Reverse a String."

Don't force Streams.

Simply:

```java
String reversed =
        new StringBuilder(str)
                .reverse()
                .toString();
```

is better.

**Knowing when NOT to use Streams is part of being good at Streams.**

# 21. Check palindrome

String str = "madam";

This is actually a nice Stream solution.

String reversed = new StringBuilder(str)

# 22. Word frequency ⭐⭐⭐

Map<String, Long> frequency =

# 🚨 EPAM interview traps

### Trap 1 — `chars()` gives `IntStream`

```java
str.chars()
```

not:

```java
Stream<Character>
```

Use:

```java
.mapToObj(c -> (char) c)
```

when you need `Character`.

---

### Trap 2 — `distinct()` ≠ frequency

This:

```java
str.chars().distinct()
```

only tells you:

> Which characters are unique in terms of occurrence in the resulting stream?

It does **not** tell you how many times each character occurred.

For frequency:

```java
groupingBy(..., counting())
```

---

### Trap 3 — HashMap doesn't guarantee order

If the question says:

> "Find the first non-repeating character."

Think:

```text
Frequency + encounter order
        ↓
LinkedHashMap
```

---

### Trap 4 — `map()` vs `mapToInt()`

```java
Stream<Integer>
```

→

```java
.mapToInt(Integer::intValue)
```

→

```java
IntStream
```

Then:

```java
sum()
average()
min()
max()
```

---

### Trap 5 — Don't force Streams everywhere

If the interviewer asks:

> Reverse a String.

This:

```java
new StringBuilder(str).reverse().toString()
```

is perfectly good.

You don't get bonus points for writing a 4-line Stream solution to a 1-line problem.
