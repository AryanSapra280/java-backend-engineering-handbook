### Q10. How do sealed classes work?

The important pieces are:

```java
sealed interface Payment
    permits CardPayment, UpiPayment {
}
```

Then the permitted implementations must declare one of these:

```java
final class CardPayment implements Payment {
}
```

or

```java
sealed class CardPayment implements Payment
    permits CreditCardPayment {
}
```

or

```java
non-sealed class CardPayment implements Payment {
}
```

So the hierarchy can be:

```text
Payment (sealed)
   │
   ├── CardPayment (final)
   ├── UpiPayment (non-sealed)
   └── CashPayment (sealed)
```

The key idea is:

**`sealed` → restrict inheritance**  
**`permits` → specify who is allowed**  
**`final` → stop inheritance completely**  
**`non-sealed` → reopen inheritance**

### Interview answer

> **"A sealed class or interface defines a restricted inheritance hierarchy. Using the `permits` clause, we specify which classes are allowed to extend or implement it. Those permitted subclasses must then be declared as `final`, `sealed`, or `non-sealed`, which determines whether their own hierarchy can be extended further."**

That's enough for Q10.

## Q13. Why would you use sealed classes/interfaces?

The core reason is **to control the inheritance hierarchy**.

Imagine you have:

```java

    permits CardPayment, UpiPayment, CashPayment {
}
```

You are telling Java:

> "These are the only types that are allowed to be `Payment` implementations."

### Why is that useful?

**1. Controlled design**

You know the complete set of possible implementations.

```text
Payment
 ├── CardPayment
 ├── UpiPayment
 └── CashPayment
```

Instead of allowing any class anywhere in the application to implement `Payment`.

**2. Better maintainability**

When the domain has a fixed set of possibilities, the hierarchy is explicit and easier to understand.

**3. Works well with pattern matching**

Sealed hierarchies are particularly useful when combined with modern Java pattern matching because the compiler knows the permitted types.

### Q14. What are Java Records?

This one **you have actually used**, so we'll distinguish it from the sealed-class questions.

A **record** is a concise way to create a class primarily meant to hold data.

Instead of:

```java
class Employee {
    private final String name;
    private final int age;

    public Employee(String name, int age) {
        this.name = name;

    // hashCode()
    // toString()
```

you can write:

```java
record Employee(String name, int age) {
}
```

Java automatically provides the important data-carrier functionality such as the constructor, accessors, `equals()`, `hashCode()`, and `toString()`.

### Key point

A record is **not simply "a replacement for every POJO."**

It's particularly useful when the object is primarily a **data carrier** and you don't need mutable state.

## Q17. What are Lambda Expressions?

A **lambda expression** is a concise way of representing a function/behavior that can be passed around as a value. It was introduced in **Java 8** and is mainly used with **functional interfaces**.

### Basic example

Without lambda:

```java
List<String> names = List.of("Aryan", "Rahul");

names.forEach(new Consumer<String>() {
    @Override
    public void accept(String name) {
        System.out.println(name);
    }
});
```

With lambda:

```java
names.forEach(name -> System.out.println(name));
```

Much less boilerplate.

### Another example

```java
Comparator<Integer> comparator =
        (a, b) -> a - b;
```

Here:

```text
(a, b) -> a - b
   ↑          ↑
parameters   body
```

### Important interview point

A lambda **doesn't exist independently as a normal object/function type** in Java. It provides an implementation for a **functional interface**.

For example:

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}
```

Then:

```java
Calculator addition = (a, b) -> a + b;
```

### Interview answer for you

> **"Lambda expressions were introduced in Java 8. They provide a concise way to represent behavior and pass it as a value, reducing boilerplate code. They are commonly used with functional interfaces, Streams, collections, and asynchronous programming. I've used lambda expressions extensively with Streams and collection processing."**

### Likely follow-up

**"What is the relationship between Lambda and Functional Interface?"**

> **"A lambda expression provides the implementation of the single abstract method of a functional interface."**

## Q18. What are Functional Interfaces?

A **functional interface** is an interface that has **exactly one abstract method**.

Example:

```java
@FunctionalInterface
interface Calculator {
    int add(int a, int b);
}
```

It can then be used with a lambda:

```java
Calculator c = (a, b) -> a + b;
```

Java provides many built-in functional interfaces:

```text
Predicate<T>  → T → boolean
Function<T,R> → T → R
Consumer<T>   → T → void
Supplier<T>   → () → T
```

### Interview answer

> **"A functional interface is an interface with exactly one abstract method. It can be implemented using a lambda expression or method reference. Java provides built-in functional interfaces such as Predicate, Function, Consumer and Supplier, and we can also define our own using the @FunctionalInterface annotation."**

One nuance: **default and static methods don't count as abstract methods**, so an interface can have multiple default/static methods and still be functional.

## Q19. What is the Date & Time API?

The **Date & Time API was introduced in Java 8** to provide a better, more consistent way of working with dates, times, durations, and time zones.

Before Java 8, developers commonly used older APIs such as:

```java
Date
Calendar
```

The Java 8 API is in:

```java
java.time
```

### Important classes

| Class | Purpose |
|---|---|
| `LocalDate` | Date without time |
| `LocalTime` | Time without date |
| `LocalDateTime` | Date + time, no timezone |
| `ZonedDateTime` | Date + time + timezone |
| `Instant` | Point on the UTC timeline |
| `Duration` | Amount of time, generally time-based |
| `Period` | Amount of time, generally date-based |

Example:

```java
LocalDate date = LocalDate.now();

LocalDateTime now = LocalDateTime.now();

ZonedDateTime indiaTime =
        ZonedDateTime.now(ZoneId.of("Asia/Kolkata"));
```

### Why is it better?

One major advantage is that the newer date/time classes are **immutable and thread-safe**, unlike the old `Calendar`/`Date` usage patterns.

For example:

```java
LocalDate date = LocalDate.of(2026, 10, 8);

LocalDate nextDay = date.plusDays(1);
```

`date` itself isn't modified; a new value is returned.

### Interview answer

> **"The Java 8 Date and Time API was introduced to provide a modern API for handling dates, times, durations and time zones. It is available under `java.time` and provides classes such as LocalDate, LocalTime, LocalDateTime, ZonedDateTime and Instant. These classes are immutable and thread-safe, which makes them easier and safer to work with compared with the older date and calendar APIs."**

### Likely follow-up

**`LocalDateTime` vs `ZonedDateTime`?**

> **"LocalDateTime represents a date and time without timezone information, whereas ZonedDateTime represents a date and time along with a specific timezone."**

## Q20. What are Method References?

A **method reference** is a shorter way of writing a lambda expression when the lambda simply calls an existing method.

For example:

```java
names.forEach(name -> System.out.println(name));
```

can become:

```java
names.forEach(System.out::println);
```

The syntax is:

```text
Class/Object :: methodName
```

Examples:

```java
String::length
System.out::println
Integer::parseInt
```

There are four common forms:

```text
1. Static method
   Integer::parseInt

2. Instance method of a particular object
   System.out::println

3. Instance method of an arbitrary object of a particular type
   String::toUpperCase

4. Constructor reference
   ArrayList::new
```

### Interview answer

> **"A method reference is a concise alternative to a lambda expression when we're simply referring to an existing method. It uses the `::` syntax. For example, `name -> System.out.println(name)` can be written as `System.out::println`. Method references are commonly used with functional interfaces and Streams."**

And yes, **you've used method references**, so you can confidently say that.
