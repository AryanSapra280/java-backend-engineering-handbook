# How I'll teach each function

We won't just do:

> "Here's the answer."

Instead, each section will follow this format:

### Problem

```text
Find the second-highest distinct salary.
```

### Input

```java
List<Integer> salaries =
    List.of(50000, 70000, 90000, 90000, 60000);
```

### Solution 1 — `sorted()`

```java
int secondHighest = salaries.stream()
        .distinct()
        .sorted(Comparator.reverseOrder())
        .skip(1)
        .findFirst()
        .orElseThrow();
```

### Solution 2 — `max()` twice

```java
int max = salaries.stream()
        .max(Integer::compareTo)
        .orElseThrow();

int secondHighest = salaries.stream()
        .filter(s -> s < max)
        .max(Integer::compareTo)
        .orElseThrow();
```

### Solution 3 — `TreeSet`

Sometimes an interviewer may ask:

> "Can you do this without sorting the entire list?"

Then:

```java
int secondHighest = salaries.stream()
        .collect(Collectors.toCollection(TreeSet::new))
        .descendingSet()
        .stream()
        .skip(1)
        .findFirst()
        .orElseThrow();
```

Then we'll discuss:

```text
Which solution is easiest?
Which is more efficient?
What happens with duplicates?
What happens with an empty list?
What happens with only one distinct value?
```

**That is the level I want you prepared to answer at.**

# Let's start FUNCTION 1

## 1. Filter even numbers

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);
```

### Approach 1 — `filter`

```java
List<Integer> result = numbers.stream()
        .filter(n -> n % 2 == 0)
        .toList();
```

Output:

```text
[2, 4, 6]
```

This is the fundamental pattern:

```text
stream
  ↓
filter(condition)
  ↓
collect
```

---

# 2. Square every number

```java
List<Integer> result = numbers.stream()
        .map(n -> n * n)
        .toList();
```

Output:

```text
[1, 4, 9, 16, 25, 36]
```

Remember:

### `filter` = select

```java
.filter(n -> n % 2 == 0)
```

### `map` = transform

```java
.map(n -> n * n)
```

This distinction is **fundamental**.

---

# 3. Sum numbers

### Approach 1 — `mapToInt().sum()`

```java
int sum = numbers.stream()
        .mapToInt(Integer::intValue)
        .sum();
```

### Approach 2 — `reduce()`

```java
int sum = numbers.stream()
        .reduce(0, Integer::sum);
```

### Approach 3 — `collect()`

You technically can write custom collection logic, but **don't use it here**. `mapToInt().sum()` is clearer.

### Interview point

If the interviewer asks:

> Why `mapToInt()`?

Because:

```java
Stream<Integer>
```

contains boxed `Integer` objects, while:

```java
IntStream
```

works with primitive `int` values and provides operations such as:

```java
sum()
average()
min()
max()
```

---

# 4. Find maximum

### Approach 1

```java
int max = numbers.stream()
        .max(Integer::compareTo)
        .orElseThrow();
```

### Approach 2

```java
int max = numbers.stream()
        .mapToInt(Integer::intValue)
        .max()
        .orElseThrow();
```

For integers, I would generally prefer:

```java
mapToInt().max()
```

because it's very expressive.

```java
int min = numbers.stream()

        .min()
        .orElseThrow();
```

```java
double average = numbers.stream()
```

# 9. Does ANY number satisfy the condition?

```java
boolean result = numbers.stream()
        .anyMatch(n -> n > 5);
```

Output:

```text
true
```

Think:

```text
anyMatch = OR
```

# 10. Do ALL numbers satisfy it?

```java
boolean result = numbers.stream()
        .allMatch(n -> n > 0);
```

Think:

```text
allMatch = AND
```

---

# 11. Does NONE satisfy it?

```java
boolean result = numbers.stream()
        .noneMatch(n -> n < 0);
```

Think:

```text
noneMatch = nobody satisfies condition
```

These three are important because they're **short-circuiting terminal operations**.

```java
List<Integer> top3 = numbers.stream()
```

```text
    ↓
```

# 15. Second-largest distinct number

This one is important enough to memorize as a pattern:

```java
int secondLargest = numbers.stream()
        .distinct()
        .sorted(Comparator.reverseOrder())
        .skip(1)
        .findFirst()
        .orElseThrow();
```

```text
distinct
   ↓

   ↓

   ↓
```

# 16. Last element

For a `List`:

```java
int last = numbers.stream()
        .reduce((a, b) -> b)
        .orElseThrow();
```

But I'd also tell an interviewer:

> "If I specifically have a `List`, `list.get(list.size() - 1)` is simpler and more efficient. I wouldn't force Streams into every problem."

**That's an important interview mindset.**

Streams are a tool, not a religion.
